# gokbanjung 2차 설계서 — 발표·카드·의견 달기·다국어·사용설명서

작성일: 2026-09-27 · 상태: 사용자 검토 대기 · 1차 설계서: `2026-09-27-gokbanjung-design.md`

## 1. 목표와 확정된 결정

comefollowme에서 남은 기능 3가지를 옮기고, 사이트를 4개 언어로 넓히고, 사용자용 사용설명서를 5가지 형식으로 만든다.

| 항목 | 결정 |
|---|---|
| 발표 모드 | 교사·관리자가 함께 생각하기 답글을 골라 순서대로 전체 화면 발표. 목록은 **교사 기기에 저장** |
| 인용 카드 | 답글을 이미지 카드로 저장·공유. 3가지 크기, 기존 배경 20종 |
| 의견 달기 ⓐ | **절 번호 기준**. 본문을 싣지 않고 절 + 짧은 인용 + 생각 |
| 의견 달기 ⓑ | **본문 싣고 형광펜**. 운영자가 권한을 확인하고 출처와 함께 올린 본문에만 |
| 다국어 A | 브라우저 자동 번역을 방해하지 않게 하고 "🌐 다른 언어" 안내 제공 |
| 다국어 C | **스페인어(es)**, **필리핀어/타갈로그(fil)** 정식 추가. 한/영과 같은 언어 버튼 |
| 사용설명서 | 사용자(참여자)용. PDF·HWPX·DOCX는 **한국어판·영어판 따로**, HTML·HTML 전자책은 한 파일에 언어 버튼 |
| 작업 순서 | ① 발표 → ② 카드 → 다국어 A → 다국어 C → ③ⓐ → ③ⓑ → 사용설명서 |

DB 원칙은 1차와 같다: 기존 Supabase 공유, **추가만**, 서버 API 경유, 기존 표 변경 금지.

## 2. 조각 1 — 발표 모드 + 골라 담기

- 위치: `/p/<slug>`에서 교사·관리자에게만 `발표 준비` 버튼. 답글마다 `☆ 담기`.
- 발표 목록: 담은 답글 id의 순서 배열. `localStorage` 키 `ggc_present:<actorId>:<promptId>`. ↑↓ 순서 변경, 빼기.
- `발표 시작` → 전체 화면 오버레이(`requestFullscreen`, 실패해도 오버레이로 동작). 첫 장 = 질문, 이후 답글 한 장씩.
- 조작: ←/→·스페이스·화면 좌우 터치·버튼, Esc 종료. `이름 숨기기` 토글(숨기면 "익명"도 표시 안 함), 언어 전환은 사이트 언어 버튼 사용.
- 삭제된 답글이 목록에 있으면 조용히 건너뛴다.
- 순수 함수 `src/lib/present-queue.ts`: `toggle(list,id)`, `move(list,id,delta)`, `resolve(list, replies)`(없는 id 제거) — 단위 테스트.

## 3. 조각 2 — 인용 카드 이미지

- 답글마다 `카드로 저장`. 미리보기 모달: 크기(정사각 1080×1080 / 세로 1080×1920 / 가로 1920×1080), 배경(기존 `src/data/card-backgrounds.json` 20종), `작성자 표시` 토글.
- 카드 내용: 질문 제목, 답글 본문(길면 줄바꿈·말줄임), 작성자, 날짜, 하단 "곡반정와드 · 함께 생각하기".
- Canvas로 기기 안에서 생성(서버 전송 없음). ①의 Insight 카드 그리기 코드를 재사용할 수 있으면 재사용.
- `이미지 저장`(PNG 다운로드), 휴대폰에서 `navigator.canShare({files})`이면 `공유`.
- 순수 함수 `wrapText(ctx-free measure, text, width, maxLines)`를 분리해 테스트.

## 4. 다국어 A — 브라우저 번역

- `translate="no"`·`notranslate`가 사용자 글과 메뉴에 걸려 있지 않은지 점검하고 제거(로고·이름 등 고유명사만 예외).
- `<html lang>`을 현재 언어로 정확히 유지(이미 적용).
- ☰ 메뉴와 언어 버튼 옆에 `🌐` → "다른 언어로 보기" 안내 모달: 안드로이드 Chrome/삼성 인터넷, 아이폰 Safari, PC Chrome/Edge에서 번역 켜는 방법(4개 언어로).

## 5. 다국어 C — 스페인어·필리핀어 정식 추가

### 방식 (코드 950곳을 고치지 않는 설계)
- `Lang = "ko" | "en" | "es" | "fil"`.
- 기존 `t(ko, en)` 호출은 그대로 둔다. `t`는 lang이 es/fil이면 **한국어 원문을 키로** 번역 사전(`src/i18n/es.json`, `src/i18n/fil.json`)에서 찾고, 없으면 영어로 대체.
- `Localized`(교육과정 제목·경전 범위·가이드·오류 메시지 등 `{ko,en}` 데이터)도 같은 사전으로 조회하는 `pick(localized, lang)` 도입.
- 추출 스크립트 `scripts/i18n-extract.ts`: 소스의 `t("…","…")`, `L("…","…")`, `{ko:"…",en:"…"}`와 curriculum/guide 데이터를 모아 `src/i18n/catalog.json`(ko→en) 생성.
- 번역: Claude가 catalog 전체를 es·fil로 1차 번역해 사전 파일에 넣는다. **기계 번역이므로 와드의 원어민 확인을 권장**(설명서에 안내).
- 테스트: catalog의 모든 키가 es·fil 사전에 있고 비어 있지 않음, 변수 자리표시(숫자·`{…}`)가 보존됨.

### 연결되는 곳
- 언어 버튼: `한국어 · EN · ES · FIL`(좁은 화면은 선택 상자).
- 자동 선택 `initialLang`: 기기 언어 `es*`→es, `fil*`/`tl*`→fil 추가. 그 외 규칙은 기존과 같음.
- 공식 교회 링크 `lang=` 코드: ko→kor, en→eng, es→spa, fil→tgl.
- 날짜·시간 표시 `Intl` 로케일: es-ES, fil-PH.
- 사용자가 쓴 글은 번역하지 않는다(다국어 A의 브라우저 번역으로 가능).
- `/guide` 페이지와 `사용설명서.html`도 4개 언어.

## 6. 조각 3ⓐ — 절 번호 기준 의견 달기

- 새 표 `ggc.verse_notes(id, owner_id, book_id, chapter, verse_start, verse_end, quote ≤200자, body ≤3000자, author ≤50, status, created_at)`, `ggc.verse_note_reactions(note_id, owner_id)`, `ggc.verse_note_comments(id, note_id, owner_id, author, body ≤1500, created_at)` — 추가만.
- 책·장·절 검증은 기존 `src/lib/scriptures.ts`의 87권 목록과 장 수를 사용(절 상한은 서버에서 1~200 범위 + 끝 절 ≥ 시작 절).
- 화면
  - 주차 페이지 "이번 주 다른 사람들의 생각"에 `절에 의견 달기` 버튼: 이번 주 경전 범위의 책·장이 기본 선택.
  - 경전 읽기(`/scriptures`)의 장 화면에서 절 번호를 누르면 그 절 의견 목록 + 쓰기.
  - 목록은 절 순서로 묶여 보이고, 하트·댓글·본인 삭제(함께 생각하기와 같은 동작, 같은 0.8초 임시 저장).
- 인용은 200자로 제한하고 "공식 원문 열기" 링크를 항상 함께 표시.

## 7. 조각 3ⓑ — 본문 싣고 형광펜 (권한 확인된 본문만)

- 새 표 `ggc.lesson_texts(id, week, lang, title, body_markdown ≤200KB, source_url, rights_note, confirmed_by, status draft/published, version, created_at)`와 `ggc.text_notes(id, lesson_text_id, version, owner_id, anchor jsonb, quote ≤300, body ≤3000, author, created_at)` + 하트·댓글 표 — 추가만.
- 운영자(관리자·교사) `본문 올리기`: 주차·언어 선택 → 본문 붙여넣기(comefollowme의 클립보드→Markdown 변환 재사용) → **"이 본문을 와드 사이트에 게시할 권한이 있음을 확인합니다" 체크 필수** + 출처 주소 필수 → 미리보기 → 게시. 본문 위에 출처·저작권 표시가 항상 붙는다.
- 읽기 화면 `/week/<n>/text`: 문장을 선택하면 `형광펜`(나만 보기, 기기 저장)과 `의견 달기`(공개). 의견은 텍스트 위치 기준(앞뒤 문맥 포함) 앵커로 저장해, 본문이 조금 수정돼도 최대한 제자리에 붙고, 못 찾으면 "원래 문장" 인용과 함께 목록에 표시.
- 다른 사람 의견이 달린 문장은 옅게 밑줄, 누르면 옆(태블릿·PC) 또는 아래(휴대폰)에 의견 목록.
- 올라온 본문이 없으면 이 기능은 보이지 않고 3ⓐ만 보인다.
- 순수 함수 `src/lib/text-anchor.ts`: `makeAnchor(text, start, end)`, `locate(text, anchor)` — 단위 테스트(수정된 본문에서 재배치, 못 찾음 처리).

## 8. 사용설명서 (사용자용)

- 원본: `src/data/guide.ts`의 참여자용·도움말 부분 + 새 기능(발표는 교사용이라 제외, 카드·절 의견·본문 의견·언어 추가).
- 화면 사진: 로컬 연습 데이터로 휴대폰 폭(390px) 캡처, 한국어·영어 각각.
- 생성물 (`바탕화면\gokbanjung\사용설명서(사용자용)\`):
  - `곡반정와드_사용설명서_한국어.pdf` / `..._English.pdf`
  - `..._한국어.docx` / `..._English.docx`
  - `..._한국어.hwpx` / `..._English.hwpx`
  - `곡반정와드_사용설명서.html` (한 장, KO/EN/ES/FIL 버튼 자동 선택)
  - `곡반정와드_사용설명서_전자책.html` (표지·목차·장 단위 쪽 넘김·진행 표시, 언어 버튼, 오프라인 동작)
- 도구: DOCX는 docx 스킬, PDF는 pdf 스킬, HWPX는 hwp(kordoc) 스킬의 Markdown→HWPX 변환. 생성 스크립트 하나로 다시 만들 수 있게.
- 검사: 각 파일을 다시 열어 제목·목차·그림 수 확인, PDF는 페이지 이미지로 확인.

## 9. 검증

- 새 순수 함수·서비스는 테스트 먼저(TDD). 전체 `npm test`, `npm run build`.
- 헤드리스 Edge로 390/820/1280px, 4개 언어, 발표 모드 키보드 조작, 카드 저장, 형광펜 선택 확인.
- 운영 DB 적용은 1차와 같이 `DB업데이트_SQL편집기용.sql`을 다시 만들어 사용자가 SQL 편집기에서 실행(추가만, 두 번 실행 안전).

## 10. 범위 밖

다른 사람이 쓴 글의 자동 번역(B안), 발표 목록 서버 저장, 본문 자동 수집(URL만 넣으면 가져오기), 사용설명서 es/fil 문서 파일(HTML 두 종은 4개 언어 포함).

## 11. 위험과 대응

| 위험 | 대응 |
|---|---|
| 3ⓑ 저작권 | 운영자 권한 확인 체크 필수, 출처 상시 표시, 운영자가 언제든 비공개 전환 |
| es/fil 기계 번역 품질 | 원어민 확인 권장 안내, 사전 파일만 고치면 바로 반영 |
| 한국어 원문을 키로 쓰는 사전은 원문 수정 시 번역이 끊김 | 추출 스크립트가 새/사라진 키를 알려 주고, 테스트가 빠진 번역을 잡음. 빠지면 영어로 대체되어 화면이 깨지지 않음 |
| 작업량이 큼 | 조각마다 커밋·배포 가능하게 쪼개서 진행 |
