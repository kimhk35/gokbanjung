강점52주 학습, 퀴즈, 학습지, 교사·관리자 도구, AI 보조와드 일정, 다른 사람 의견 보기, 발표 모드, 인용 카드, 절·원문 메모양쪽 기능을 모두 살림
데이터Supabase(ggc 스키마)다른 소유자의 Supabase①의 DB에 표만 추가. ②의 기존 데이터는 옮기지 않음

통합 원칙

  • 뼈대는 ①, 기능은 ②에서: ②의 화면 동작과 글자 수 제한 등은 따르되, 저장은 모두 서버 API를 거친다.
  • DB는 더하기만(additive): create ... if not exists 로 새 표만 만들고 기존 표·정책은 바꾸지 않는다. 그래서 운영 중인 기록이 안전하다.
  • 권한은 매 요청마다 서버가 DB로 다시 확인한다(브라우저를 믿지 않는다).
  • AI 기능은 OPENAI_API_KEY가 있을 때만 켜진다. 키가 없으면 자동으로 꺼져 비용이 0원이다.
  • 휴대폰(390px)과 태블릿을 먼저 생각한 화면: 하단 메뉴, 큰 누름 영역(44px 이상), 글자 크기 조절, 다크 모드.

요청이 처리되는 길

  1. 브라우저가 /api/경로 로 요청한다 (src/lib/client.ts의 api 함수).
  2. src/app/api/[...path]/route.ts 가 받아 손님 쿠키·로그인으로 누구인지(actor) 확인한다.
  3. 와드·생각하기·메모·Insight 경로(ward/, think/, notes/, insight/, home/activity)는 src/lib/community-api.ts 로, 나머지는 src/lib/service.ts 로 간다.
  4. 각 기능 함수는 privileged() 트랜잭션 안에서 권한을 DB로 다시 확인한 뒤 읽고 쓴다.
  5. 응답은 JSON. 오류는 코드(예: session_required)로 돌려주고 화면이 한국어/영어 문장으로 바꿔 보여 준다.

운영 DB에 반영하는 법

  1. npm run db:editor-sql 로 DB업데이트_SQL편집기용.sql 을 만든다 (세 마이그레이션 + 포스터 버킷).
  2. Supabase 웹 → SQL Editor 에 파일 내용을 붙여 넣고 Run. 마지막 결과가 '완료: …(기존 기록 유지)'이면 성공.
  3. 또는 DATABASE_URL 을 알고 있으면 npm run db:update (잘못 붙여 넣으면 한국어로 이유를 알려 줌).
  4. 여러 번 실행해도 안전하다(if not exists).

순서가 중요합니다: DB 반영 → 그다음 main 브랜치에 올리기(자동 배포). 새 표가 없는데 새 코드가 먼저 배포되면 해당 기능만 오류가 납니다.

배포 흐름

  1. 작업은 별도 브랜치(예: phase2)에서 하고 GitHub에 올린다.
  2. DB 변경이 있으면 5장의 방법으로 먼저 반영한다.
  3. main 에 합쳐 올리면 Vercel이 자동으로 빌드·배포한다(바탕화면 폴더의 3_배포.cmd 로도 가능).
  4. 배포 뒤 4개 언어로 홈·와드·생각하기·경전 읽기를 한 번씩 열어 확인한다.

안드로이드 앱

  • 방식: TWA(Trusted Web Activity). 앱이 크롬으로 사이트를 전체 화면으로 여는 구조라, 사이트를 고치면 앱도 바로 바뀐다. 앱 다시 만들기는 아이콘·이름을 바꿀 때만 필요.
  • 패키지 이름 kr.gokbanjung.app, 서명 인증서 SHA-256은 public/.well-known/assetlinks.json 과 일치해야 주소창 없이 열린다.
  • 빌드: android/build.ps1 (JDK 17·Android SDK·Bubblewrap이 C:/ggc-android 에 설치됨). 버전을 올릴 때 twa-manifest.json 의 appVersionCode 를 1 올린다.
  • 서명 열쇠는 %USERPROFILE%/.claude/secrets/gokbanjung-release.keystore, 비밀번호는 같은 폴더 .env 의 GOKBANJUNG_KEYSTORE_PASSWORD. 저장소에는 절대 넣지 않으며(.gitignore 처리) 따로 백업해야 한다. 잃어버리면 같은 앱으로 업데이트할 수 없다.

사이트 보안 요점

  • 비밀 키는 코드·저장소에 없음. 서버 환경변수와 개인 비밀 폴더에만 보관.
  • 업로드 파일은 확장자와 파일 첫 바이트를 함께 확인(이름만 바꾼 파일 거부), 크기 제한, 학습지 파일은 서버에 저장하지 않음.
  • 보안 헤더(CSP)로 허용된 곳에서만 이미지·스크립트를 불러옴.
  • 손님은 쿠키로 구분되며 자기 글만 지울 수 있고, 관리자는 숨김·삭제 가능.

  • 새 기능마다 자동 테스트: 와드 일정 시간 계산(한국 시간), 권한, 발표 대기열, 텍스트 위치 찾기, 학습지 문항 추출, 번역 병합, 색 명암비 등.

  • src/components/shell.tsx 37행의 린트 경고(효과 안에서 상태 변경)는 원래 코드에 있던 것. 동작에는 문제 없음.
  • 스페인어·필리핀어에서 숫자 등이 끼어 있는 일부 문장(템플릿 문장)은 영어로 보임.
  • 경전 본문은 교회 공식 사이트에서 가져오므로 그쪽이 느리거나 막히면 '공식 사이트에서 열기' 링크로 대신한다.
  • 이 PC에서는 한글 프로그램 자동화가 파일을 열지 못해, HWPX는 kordoc으로 직접 만든다.
  • 안드로이드 앱은 휴대폰에 크롬이 있어야 가장 잘 동작한다.

8. 함께 개발하는 법

처음 준비

  1. GitHub 저장소 gokbanjung 에 초대를 받아 내려받는다(git clone).
  2. npm ci 로 부품 설치, .env.example 을 .env.local 로 복사해 값 채우기(값은 관리자에게 따로 받기).
  3. npm run dev -- --port 3100 → http://localhost:3100. DATABASE_URL 이 없으면 PGlite 로 내 컴퓨터 안에서 동작.

새 기능을 넣는 순서

  1. DB가 필요하면 supabase/migrations 에 새 파일(날짜_이름.sql)을 만들고 create ... if not exists 로만 작성.
  2. src/lib/기능.ts 에 서버 로직(zod로 입력 검사, privileged() 안에서 권한 확인).
  3. 읽기·쓰기 경로를 src/lib/community-api.ts(또는 service.ts)에 연결.
  4. 화면은 src/components/…, 모든 문구는 t("한국어", "English")로 작성.
  5. npm run i18n:extract → 새 문장을 스페인어·필리핀어로 번역(TSV) → npm run i18n:merge es 폴더 / fil 폴더 → missing 0 확인.
  6. tests/ 에 테스트 추가 → npm test, npm run lint, npm run build.
  7. 설명서가 바뀌면 src/data/guide.ts 수정 → npm run guide:build, 필요하면 사용설명서 다시 만들기(부록).

지켜 주세요

  • 기존 표·정책을 바꾸는 마이그레이션 금지(운영 기록 보호).
  • 키·비밀번호를 코드·커밋·메신저에 넣지 않기.
  • 색은 theme.css 의 이름(--navy, --gold …)만 사용 → 다크 모드와 명암비가 자동으로 맞음.
  • 새 화면은 휴대폰 390px에서 가로로 넘치지 않는지 확인.

다음에 해 볼 만한 것

  • 스페인어·필리핀어 템플릿 문장까지 번역되도록 번역 함수 확장.
  • 와드 일정 알림(구독형 달력 주소, ICS).
  • Insight·질문 모음 인쇄용 PDF.
  • 앱을 구글 플레이에 비공개 테스트로 올려 업데이트 자동화.
